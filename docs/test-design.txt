Decision-to-decision graphs (implementation as supplied)
-------------------------------------------------------
Contiguous statements between decisions are grouped. The graphs describe the
existing code paths. The decision tables describe expected behaviour.

DiscountService
  Entry → input validation → subtotal → quantity loop → accessory loop
    → coupon decisions → subtract coupon, floor and round → return result
  Quantity loop: accessory? yes → next item; no → choose tier and threshold
    → accumulate line discount → next item.
  Accessory loop: non-accessory or fewer than 3? yes → next item;
    no → accumulate accessory discount → next item.
  Coupon decisions:
    blank/absent? yes → zero; no → DISCOUNT10?
    DISCOUNT10 yes → product total >= £100? yes → £10 capped; no → zero.
    DISCOUNT10 no → VIP15? no → throw; yes → VIP AND product total >= £150?
      yes → £15 capped; no → zero.
  Q1–A3 exercise the two loops. C1–C10 and the absent coupon cases exercise
  the coupon exits. Zero-priced merchandise covers a final total of zero.

DeliveryService
  Entry → validate inputs → VIP? yes → zero; no → Express?
    Express yes → £9.99; no → eligible for free Standard?
      yes → zero; no → £4.99.
  D1–D4 exercise the tier, option and threshold outcomes. StructuralCoverageTest
  adds the negative total rejection. The VIP-true outcome in the private
  Standard eligibility helper is unreachable because the earlier VIP return
  handles every VIP input. Invalid quantities/negative prices in the discount
  validator are prevented by ordinary CartItem and Product APIs.

OrderService
  Entry → validate arguments → empty cart? yes → throw; no → calculate discounts
    → pass total to delivery → add fee → return order result.
  D5 exercises the non-empty path. OrderIntegrationTest.testRejectsEmptyOrder
  exercises the rejection path. The mock test targets the delivery handoff.
  For a non-VIP order, a valid DISCOUNT10 coupon leaves at least £90 and
  VIP15 is unavailable, so a coupon alone cannot cross the £75 Standard
  delivery threshold for a non-VIP. D5 uses a product discount instead.

Coverage check
--------------
Measured with the JaCoCo 0.8.15 agent and core shipped by VS Code Test Runner
for Java. Both runs include the mock test using Mockito from the Week 4
solution. See Coverage/index.html for the annotated final report.

                      Tests  Failures   Lines        Branches
Original baseline       52     12       235/284      79/108
With structural tests   62     12       244/284      86/108

The added validation tests cover all measured cart branches and one more
delivery validation branch. The final run includes two later requirements
tests for the stated coupon cap and unsupported delivery option names.
JUnit logs are in build/test-results/.
The Mockito failure corroborates the real-service delivery test. Delivery
received £100.00 when it should have received the discounted £90.00.
